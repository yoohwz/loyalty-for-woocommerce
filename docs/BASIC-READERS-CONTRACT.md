## Value and period invariants

- Member count is distinct users with a role in saved `loyalty_levels_roles`; no forced customer fallback. Registered role key presence establishes native membership, including boolean-false grants; population, customer admission and level fallback share that semantics. Missing role metadata establishes no native role membership. Duplicate or malformed candidate role metadata makes the aggregate Unavailable. Aggregate admission proves the usual serialized boolean role/capability array in SQL, with case-sensitive keys and lengths from the native role registry; candidates carrying unregistered custom capabilities, nonboolean grants or an unknown capability shape also make the aggregate Unavailable rather than silently changing the population. Export preflight follows the same proof.
- Available/earned metadata is read without integer/float conversion. Missing, duplicate or malformed values are Unavailable. Exact nonnegative decimal strings may be displayed/exported, including fractions and values beyond JavaScript integer precision. A hold, allocation checkpoint or value outside the existing writer/cart numeric contract is disclosed as needing review; stored value is not a promise that spending is enabled.
- Outstanding points is current stored stock, as of the read, across current admitted members. Exact SQL DECIMAL aggregation accepts at most 30 integer and 30 fractional digits; unsupported precision makes the whole stock Unavailable. No normalization or inferred history.
- Flow evidence uses `YOWCL_Ledger_V2::inspect` with bounded snapshot source lookup, the same canonical/legacy distinction as `YOWCL_Free_Core::history_amount`. All-NULL legacy rows are excluded with coverage. Malformed advertised proof makes flow totals Unavailable. No legacy amount or order marker is canonical proof.
- Gross issued includes positive canonical reward actions and `admin_reward`, without a source link. Imports, returns and reversals are excluded. Gross redeemed includes negative `points_used` with a native `checkout_redeem:<UUID>` identity and positive order ID, with zero earning delta, without a source link, and with any advertised receipt agreeing with the strict native debit. Inconsistent advertised native funding proof is Unavailable; other unproven debits have explicit coverage. Returns do not reduce gross redeemed. No net flow is presented.
- Lifetime flow accepts structurally proven pre-v2 transactions. Recent flow uses receipt `admitted_at` UTC microseconds, bounded by now and now minus 30 calendar days in the current store timezone. Missing time proof on a potentially relevant row makes that recent metric Unavailable. Log wall dates and order dates are never substituted.
- Orders using points counts distinct proven funded order IDs in the selected flow period. Redemption share is omitted in V1: the log flow population does not establish a reliable, identical qualifying Woo order denominator.
- Bounds are 5,000 proof rows, 10,000 current admitted members, 200 CSV customers per batch, 2,000 selected metadata rows per batch and 4 MiB of selected proof/metadata payload; selected configuration containers are bounded to 256 KiB. Oversized input is Unavailable/incomplete, not truncated into an exact result.
- Bounded readers never create logs, checkpoints, claims, balance metadata, import operations or reward projections. The only admitted render side effect is LOYF-10's existing idempotent unique-token helper, for the current viewer's enabled referral component.

## Display and export

Level adapts the accepted read-only highest-role helper’s stored-level precedence and highest-assigned-threshold semantics to bounded snapshot metadata, after validating configuration; progress is textual exact earned points toward the next configured threshold, without rounded percentages. Unknown rules or level produce a review message. History links to the configured existing My Account endpoint only. Ways to earn lists enabled Free rules, with First Purchase only when its native epoch is ready, and Referral only under native policy. Explicit block/shortcode placement is independent of the bubble placement toggle; account endpoint and configured labels remain respected.

The CSV schema is `record_type,user_id,email,available_points,earned_points,loyalty_level,balance_state`. `customer` rows contain minimal authorized PII; `complete` or `error` is a terminal status, not a customer. Numeric strings preserve every stored digit and spelling, prefixed by one tab to request spreadsheet text handling; raw parsers receive that documented text prefix, not a rounded number. Formula-capable text (including controls and fullwidth formula starters) is prefixed by a tab and all fields use standard CSV quoting. This spreadsheet display escape intentionally changes unsafe raw text; the export is not an import template or round-trip format. Never export tokens, receipts, source identities, addresses or payment details. A downloaded file without a final `complete` record is incomplete.

Registration follows [WordPress dynamic blocks](https://developer.wordpress.org/block-editor/how-to-guides/block-tutorial/creating-dynamic-blocks/) and [shortcodes](https://developer.wordpress.org/reference/functions/add_shortcode/). Fresh nonce acquisition uses the existing [authenticated WordPress action](https://developer.wordpress.org/reference/functions/wp_ajax_rest_nonce/). Spreadsheet escaping follows [OWASP CSV Injection](https://community.owasp.org/attacks/CSV_Injection); no promise is made that later spreadsheet rewrites preserve escaping.

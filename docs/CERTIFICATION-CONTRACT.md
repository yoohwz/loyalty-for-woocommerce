## Approved migration boundary (Plan Review6057343128)

Completed witnesses retain canonical authority. Unwitnessed source provenance is checked before evidence, target or witness writes. Same-request conservative onboarding proof admits fresh zero initialization; an authenticated pre-upgrade capture against the complete immutable historical Free1.2.2 product tree admits only the captured feature's old-Free conversion. Existing version/schema markers alone cannot establish chronology. Normal upgrades without independently verified pre-upgrade provenance remain held and have explicit per-feature resolution; no test-only environment override grants product authority. Premium-history/ambiguous footprints keep source/target bytes dormant.

Frozen conversion/recovery compares presence/type/value of only the owned pair against original pre-image or exact intended post-image, under the existing option lock/CAS and one original mysqli connection. WordPress reconnection cannot inherit that lock or replay transaction/witness writes. Target plus witness commit atomically in InnoDB; an already active caller transaction is rejected rather than implicitly committed. Different owned terms hold; another signup/login pair or unknown fields survive. Existing origin-less partial evidence holds. Per-feature authorized resolution binds displayed source/target terms, intent and choice; target/witness failure retries only that explicit intent, never boot-replays resolution or overwrites later owned edits. Existing rollback/source evidence is retained.

Reward/mail/redemption ready guards deny new held admissions; committed accounting recovery remains with existing owners. Merchant choices keep a valid current canonical pair, explicitly adopt a valid legacy source, or disable/configure supported Free terms. No balance/history/schema/role/old witness repair is admitted.

Previously completed origin-less `_before` evidence is exposed to administrators as a read-only before/migration/current assessment of owned fields only. Unknown/dormant container data is not displayed and no rollback action is introduced. Held level-up admissions still route through committed-event recovery with zero new terms, so an already committed compatibility marker can converge without another value row.

Extra points settings retain per-feature isolation: held controls are read-only, and server-side saves ignore held or absent fields under the existing options owner without creating migration evidence. All submitted editable amounts are validated before writes; First Purchase saves after the ready reward settings. Native storage failure reports which setting saves completed, rather than claiming a complete form save. This preserves independent feature owners, not a new multi-feature transaction or journal.

Level maps for explicitly submitted controls are merged from uncached live option rows after ownership. Unsubmitted level controls trigger no target read; stale pre-lock caches cannot replace dormant/other-role fields during an authorized narrow save.

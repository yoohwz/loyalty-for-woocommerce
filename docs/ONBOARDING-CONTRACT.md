# Free Quick Start lifecycle

LOYF-11 base: `95f3a7d30695ca3f75ad4ae0086a4ddbc27a6748`; read-only governance upstream: `9e3d663b9828a24eacd141216d5e6f6e22da8ca4`.

| Entry / state | Authority and persistence | Failure / retry invariant |
| --- | --- | --- |
| Inactive Free first include, before self-seeding | Conservative uncached options/schema/marker/role/HPOS/AS assessment; `loyf_onboarding_v1` UX witness | Any footprint, active upgrade, multisite, custom-role/orphan-role ambiguity, incomplete capability coverage (10,000-row limit) or read failure is review-only. An empty old schema counts as prior installation. A missing witness never proves freshness. |
| Same request after native bootstrap | Freeze generated settings footprint, cutover and narrow write-target bytes | Only the request that performed a successful durable assessment can seal the baseline. Interrupted assessment/bootstrap cannot recover writing permission on a later boot. Native customization defaults are shared from the existing owner, not guessed from absent options. |
| Invitation / six-step form / exit | Admin navigation; Back/Next/Skip are local form state; authorized POST can dismiss | No redirect, business writes, reward simulation, points mutation or role assignment. Review-only uses current raw settings and existing authoritative edit screens. |
| Explicit Launch | `manage_options`, nonce, POST, edition owner; site options mutex, native no-reconnect WPDB guard and InnoDB options | Validate all selected terms before persistence. Reject stale currency, changed protected settings, used program, incomplete migration or unknown provenance. Transactionally consume the sole writing invitation before business commits. |
| Consumed Launch → baseline settings | Bounded options transaction and raw readback; existing option names, customer-only level | Atomic baseline, including display; preserve redemption unowned fields. Existing Woo settings saves acquire database row locks even though they do not take the options mutex. A second footprint check rejects intervening writes. No balance, history, order, role or AS write occurs. My Account uses native endpoint registration/rewrite flushing after commit. |
| Baseline → selected growth | Existing First Purchase and Referral Lite save services under the same mutex; their native epoch/option owners | Skip means no economic option/epoch creation. No outer transaction is wrapped around First Purchase. Its real cutoff excludes pre-enable orders. Native reconnect is disabled while calling the services; raw reads, not warmed caches, confirm outcomes. |
| All selected writes confirmed → completion | UI witness only | Completion is never an earning/redemption/referral admission predicate. Legitimate callbacks may observe merchant-approved values during a partial Launch. |
| Failure / disconnect / stale tab | Consumed invitation remains incomplete and review-only | No automatic resume, compensation, disable/reenable or repeated service call. Current values may be partially effective; the review screen explains this and links to native settings. Completed same-attempt replay never overwrites later edits. |

The permitted partial-effective/manual-recovery protocol follows Issue #11's explicit bounded partial-failure allowance. It does not promise all-selected atomicity or undo already accepted economic events. The onboarding snapshot is UX stale-form evidence, not a migration/accounting control plane. Historical fixtures/golden data and Free version `1.2.2` remain unchanged.

Adversarial coverage targets actual unseeded activation, old-Free upgrade, isolated legacy footprints, denied HTTP writes, interrupted/unknown commits, parallel Launch and native merchant edits, and native browser navigation/Launch/exit. Existing full economic/modern-checkout/First Purchase/Referral suites remain required. Evidence labels and exact-SHA certification follow the inherited governance.
